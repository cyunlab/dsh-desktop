# Promote Stable updates when GitHub Releases are published

An Update release enters the Stable channel only when its GitHub Draft Release is published. The publication event triggers automated validation of every platform package, updater signature, uploaded object, and update path on Windows x64, Linux x64, and both supported macOS architectures before changing the Stable update manifest; a failed validation leaves the previous Stable release visible to clients. The published GitHub Release body is the sole source of release notes copied into that manifest. Promotion makes the release visible to the entire Stable channel, and its immutable platform packages are retained permanently. A bad release is withdrawn by restoring the previous manifest to stop further uptake, while affected installations recover through a newer fix release rather than automatic downgrade. This keeps the existing human release gate while preventing a separate, divergent OSS promotion process.
