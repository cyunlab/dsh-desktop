# Expose typed domain Interfaces for Desktop capabilities

Plugins consume Desktop capabilities through strongly typed, task-level domain Interfaces rather than a public string-based `invoke` method or raw Tauri commands. The Desktop capability bridge hides transport, platform differences, cancellation, state ordering, native interaction, and error normalization behind those Interfaces. The automatic-update slice introduces a private `@cyunlab/dsh-desktop-capabilities` package whose update domain exposes only ordered state observation and a request to open the Desktop-owned update surface. Its first production Adapter uses narrowly scoped Tauri IPC, while browser and test code use unavailable and in-memory Adapters. The package remains private until broader third-party capability semantics are intentionally stabilized.
