# Recover the broken first-updater Stable with a second immutable receipt

Stable `2.1.5` was admitted by the one-time first-updater bootstrap receipt, but its production downloader passed a temporary file positioned at EOF into staging. Every non-empty update therefore became an empty staged copy and failed signature verification. The repair exists in `2.1.10`, but an installed `2.1.5` necessarily executes the broken old downloader and cannot use that repair to update itself.

The existing bootstrap receipt remains immutable and the first-updater bootstrap must not be reopened. A separately named, one-time recovery path may admit the reviewed `2.1.10` release. Recovery requires protected production variables to bind the exact candidate tag, version, commit and immutable manifest SHA-256; the byte-exact current `2.1.5` Stable manifest; the sole existing first-updater receipt key and raw SHA-256; and the failed normal promotion run that demonstrated the defect. Its evidence attestations must come from the pinned reusable fresh-install workflow on GitHub-hosted runners, and both macOS targets must report verified code signing and notarization. It explicitly makes no previous-Stable upgrade claim.

Recovery shares the normal promotion workflow concurrency group. Finalization acquires the global Stable promotion lock, re-reads every admission input, writes and byte-verifies one immutable object under `dsh-desktop/recovery/receipts/`, re-reads all inputs again, and replaces Stable as the final release-content mutation. Any complete or partial recovery receipt permanently closes this recovery path. A failure after lock acquisition intentionally preserves the lock and audit material for investigation.

This recovery establishes a healthy baseline for new or manually updated installations; it cannot repair already installed `2.1.5` copies through automatic update. After recovery, a higher successor must pass the normal four-target previous-Stable-to-candidate native update gate. Once that succeeds, the temporary first-bootstrap and recovery workflow code is removed while both OSS receipts remain permanently retained.
