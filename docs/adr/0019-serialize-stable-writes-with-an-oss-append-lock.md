# Serialize Stable writes with an OSS append lock

Every repository-owned write to the Stable channel is serialized by one OSS object at `dsh-desktop/channels/stable/promotion.lock`. The normal published-release finalizer and the one-time first-updater bootstrap use the same protocol. A contender atomically creates the lock with OSS `AppendObject` at `position=0`; concurrent acquisition fails closed with a storage-side 409 or 412 response. The lock body binds a unique workflow run/attempt, promotion mode, candidate tag/commit/manifest digest, and the Stable manifest digest observed during candidate preparation.

OSS `PutObject` does not support destination `If-Match` or `If-None-Match`; the service returns `NotImplemented` for those headers. `CopyObject` conditions apply to its source, not its destination, and bucket Versioning causes `x-oss-forbid-overwrite` to be ignored. We therefore do not claim a destination-object compare-and-swap that OSS cannot provide. The append lock is the storage-side atomic coordination primitive. After acquisition, the owner re-reads and verifies Stable and the immutable candidate, writes Stable only after every other release mutation, re-reads the published bytes, verifies the lock owner, and then deletes only the lock object. Versioning retains the historical lock version.

Any error or process crash preserves the current lock and blocks later promotion. Recovery requires a human to inspect the lock bytes, workflow run, candidate, Stable current and historical versions, evidence, and bootstrap receipt when applicable. Only after determining that no writer remains active may an administrator remove the current lock marker; recovery never deletes immutable candidate, evidence, receipt, or historical Stable data.

This protocol assumes all writers authorized to mutate Stable are the two protected repository workflows. The prefix-scoped OIDC role grants deletion only for the exact lock key. An Alibaba Cloud account owner can bypass application protocols and is outside this coordination guarantee; administrative access remains a separate audited trust boundary.
